STATUS CODEX
============

Ultima actualizare: 2026-08-05 11:02 CEST
Status: FINALIZAT

Task curent
-----------
Repararea erorii SQL la generarea/citirea evenimentelor de sut si verificarea
legaturii cu turneele si Save/Load.

Cauza confirmata
----------------
- Campul Java `minute` era mapat implicit pe coloana SQL `MINUTE`, cuvant
  rezervat in H2.
- Comanda CREATE TABLE SHOT_EVENT esua la pornire. Interogarea raportata de UI
  era doar eroarea ulterioara: Hibernate incerca sa citeasca o tabela inexistenta.
- Crearea/accesarea unui turneu putea declansa prima citire Data Hub, dar nu
  algoritmul turneului stergea tabela.

Ce a fost implementat
---------------------
- `ShotEvent.minute` foloseste acum coloana sigura `EVENT_MINUTE`.
- Formatul Save Game a fost ridicat la v14.
- Save/Load include acum SHOT_EVENT, POSSESSION_PROGRESSION,
  DEFENSIVE_PRESSURE si SET_PIECE_EVENT.
- Salvarile v5-v13 raman compatibile; pentru sectiunile Data Hub inexistente se
  aplica o migrare determinista la liste goale.
- USER_UI_PREFERENCES ramane stare locala per utilizator si nu este suprascrisa
  de incarcarea unei cariere.
- Testul de aliniere a generatoarelor a fost actualizat pentru FRIENDLY_EVENT
  si tabelele Data Hub introduse dupa v8.

Verificare
----------
- SHOT_EVENT este creat cu EVENT_MINUTE, apoi scris si interogat prin repository: OK.
- Acoperire completa a manifestului Save/Load (92 tabele): OK.
- Import v14 cu ShotEvent si migrare v13 fara sectiunile Data Hub: OK.
- Preflight, schema reala, generator alignment si suitele Save/Load economie:
  22 teste rulate, toate OK dupa corectarea asteptarii versionate.

Nota de rulare
--------------
Backend-ul trebuie repornit pentru ca Hibernate sa creeze SHOT_EVENT cu schema
corecta. Nu este necesar un New Game; carierele v13 si mai vechi pot fi incarcate.

Regula de urmarire
------------------
La fiecare cerere viitoare care produce modificari, acest fisier va fi actualizat,
comis si publicat pe GitHub pana cand utilizatorul cere explicit oprirea acestei reguli.
