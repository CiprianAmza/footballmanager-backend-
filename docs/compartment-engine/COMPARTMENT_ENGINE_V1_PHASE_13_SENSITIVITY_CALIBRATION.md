# Compartment Engine V1 Phase 13

Phase 13 introduces a single non-optional imported `compartment-scoring-weights-v1.yml` catalog and a pure calibration package. The final leaf count is derived from the bound profile by `CanonicalScoringWeightCatalog`; it is not a hardcoded acceptance value. Only values consumed by the Compartment input/evaluation/sampler pipeline are active: CompartmentEngineConfig, role suitability scale/attribute overrides, and the PlayerCapabilityResolver familiarity fallback matrix. PlayerValue scale/rating/morale/fitness, role blending, and InstructionWeights remain `LEGACY_OR_NON_CANONICAL` and are excluded from the sweep.

`CanonicalScoringWeightCatalog` contains exactly 731 numeric V1 leaves and exposes discrete controls, diagnostic-only parameters, and inactive/future parameters separately. The mentality midfield transfer pair is one constrained canonical leaf: `midfield-to-attack` derives its companion defense share and is reported once. The unused context-factor and total-context clamp fields, plus `STAY_FORWARD` engagement without a live defensive consumer, remain runtime defaults but are excluded from the active catalog until a live consumer exists. Extra-time scaling and predictive interval quantiles are therefore not sensitivity leaves. `CanonicalScoringWeightSet` deep-copies the configuration pair before applying one validated override, including `aggregation.wide-redistribution-share`. Role attribute tables are bound under `match.engine.role-weights.attributes`; strict canonical role suitability fails when a live role is missing or incomplete. `ScoringSensitivityHarness` rebuilds both canonical input pipelines from immutable raw fixtures, uses only independent canonical evaluation adapters and the local score sampler, common seeds, paired seasonal deltas, and a fixed 38-match season schedule. Reports include baseline/tested pre-RNG metrics, PMF L1 delta, points and confidence intervals.

The baseline gate is league-relative. `LeagueCalibrationHarness` runs a complete 20-club home-and-away table for each of 200 seasons (76,000 matches) against a symmetric strength distribution. Acceptance uses the candidate's average rank/percentile near the middle of the table; it deliberately does not require a fixed points total such as 60, because the attainable points distribution changes with draw rate and global scoring calibration.

The baseline, selected-weight, and all-weight 200-season gates are executable tests enabled only by `compartment.calibration.long=true`; they were `NOT_RUN_BY_POLICY` in this implementation pass. All-weight runs accept `compartment.calibration.shard-index` and `compartment.calibration.shard-count`, partition the catalog deterministically, and write separate selected, baseline, and shard reports with atomic replacement. No runtime formula, default, wiring, persistence path, or feature flag is changed.

The `SHADOW_STRIKER` role is N/A for production sensitivity until it becomes a live role. It is not present in the production `PositionRoleKey` whitelist, default formations, automatic role selection, API, persistence, or runtime input. Rollout flags remain only in `application.yml` and remain false; the weights profile contains no flags.
