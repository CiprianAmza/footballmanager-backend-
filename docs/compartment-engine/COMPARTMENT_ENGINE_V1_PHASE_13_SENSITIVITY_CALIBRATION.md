# Compartment Engine V1 Phase 13

Phase 13 introduces a single non-optional imported `compartment-scoring-weights-v1.yml` catalog and a pure calibration package. The final leaf count is derived from the bound profile by `CanonicalScoringWeightCatalog`; it is not a hardcoded acceptance value. Only values consumed by the Compartment input/evaluation/sampler pipeline are active: CompartmentEngineConfig, role suitability scale/attribute overrides, and the PlayerCapabilityResolver familiarity fallback matrix. PlayerValue scale/rating/morale/fitness, role blending, and InstructionWeights remain `LEGACY_OR_NON_CANONICAL` and are excluded from the sweep.

`CanonicalScoringWeightCatalog` orders every bound leaf by stable path. `CanonicalScoringWeightSet` deep-copies the configuration pair before applying one validated override. `ScoringSensitivityHarness` rebuilds both canonical input pipelines from immutable raw fixtures, uses only independent canonical evaluation adapters and the local score sampler, common seeds, paired seasonal deltas, and a fixed 38-match season schedule. Reports are written below `target/compartment-calibration` in deterministic CSV/JSON order.

The baseline, selected-weight, and all-weight 200-season gates are executable tests enabled only by `compartment.calibration.long=true`; they were `NOT_RUN_BY_POLICY` in this implementation pass. All-weight runs accept `compartment.calibration.shard-index` and `compartment.calibration.shard-count`, partition the catalog deterministically, and write separate selected, baseline, and shard reports with atomic replacement. No runtime formula, default, wiring, persistence path, or feature flag is changed.

The `SHADOW_STRIKER` role is available for measurement only. It is not added to default formations or automatic role selection.
